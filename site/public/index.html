原理 · HOW IT WORKS

说一句意图，剩下交给 Hero

Hero 是有名字、有职责、配齐工具与技能的 AI agent。你用自然语言说出意图，分诊与编排自动完成，每一步都有确认门控——不记命令，自然语言直达。

  1. 01说出意图自然语言，不记命令
  2. 02意图分诊归类到 8 条 lane
  3. 03补齐输入缺什么问什么
  4. 04确认门控你点头才动手
  5. 05交接执行对应 Hero / workflow

意图分诊

一句意图自动归类到 bugfix / perf / refactor / research / security / prd / refresh / iterate 八条 lane，补齐输入、确认后交接。

PRD 驱动开发

给一个飞书 PRD 链接 → 孔明出设计与 Sprint 计划 → 多 Hero 并行开发 → 玄成、鹏举把关 → 合并。全程门控 + worktree 隔离。

资产保鲜

代码在变，Hero 的知识不能过时。定期扫描变化 → 刷新领航员认知 → 人工 gate 确认才生效。

进阶 · BUILD YOUR PILOT

为你的项目造一位领航员

领航员是某个服务的「只读知识层」——懂业务定位、技术栈、代码地图与对外契约。用 codegraph 六步，从一个项目生成一个 hero-<lang>-<project>。

  1. 1

    索引项目

    codegraph init -i . 首次索引；先把 .codegraph/ 加进 .git/info/exclude 防污染。

  2. 2

    探测源码布局

    别假设 src/main/java 在根——单模块与多模块差别很大，先探出真实包根。

  3. 3

    识别真实技术栈

    读 pom.xml / build.gradle 认框架，决定模板——不能默认 Spring，否则会编出不存在的依赖。

  4. 4

    组装证据包

    用 codegraph + grep 抓模块结构、入口、Feign 下游、MQ、定时任务、对外契约与语义种子。

  5. 5

    套模板生成

    frontmatter name = hero-<lang>-<project>，description 四段式（定位 / 触发词 / 路由 / 边界），正文七部分。

  6. 6

    反编造验证 + 登记

    正文引用的每个类都要 grep 命中（零编造），最后在 hero-agent-roster.md 登记一行花名册。

完整手册见仓库 docs/project-agent-cookbook.md；开荒完成后纳入 hero-refresh，即可随代码漂移自动保鲜。
