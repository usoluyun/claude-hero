了解理念

理念 · ETHOS

每一个 AI 伙伴，都该有名字、有职责、有温度。
把繁琐的庶务交给他们，把方向与判断留给人——
前路有领航 Hero 带路，实事有角色 Hero 执掌。
角色 Hero

各执一艺——架构、开发、测试、审查、安全，跨服务通用，在领航带路下协同推进，负责「具体怎么改」。

能力底座

原理 · HOW IT WORKS

说一句意图，剩下交给 Hero

Hero 是有名字、有职责、配齐工具与技能的 AI agent。你用自然语言说出意图，分诊与编排自动完成，每一步都有确认门控——不记命令，自然语言直达。

hero 修一下登录报错 hero 这个接口太慢 hero 开发工作流 <飞书 URL> hero 刷新

所有 Hero 都以 hero 开口——分诊器判断走哪条线，接管时打上 🦸 hero ▸ 标记，让你随时看见是哪位 Hero 在干活。

  1. 01说出意图自然语言，不记命令
  2. 02意图分诊归类到 8 条 lane
  3. 03补齐输入缺什么问什么
  4. 04确认门控你点头才动手
  5. 05交接执行对应 Hero / workflow

意图分诊

一句意图自动归类到 bugfix / perf / refactor / research / security / prd / refresh / iterate 八条 lane，补齐输入、确认后交接。

PRD 驱动开发

给一个飞书 PRD 链接 → 孔明出设计与 Sprint 计划 → 多 Hero 并行开发 → 玄成、鹏举把关 → 合并。全程门控 + worktree 隔离。

资产保鲜

代码在变，Hero 的知识不能过时。定期扫描变化 → 刷新领航员认知 → 人工 gate 确认才生效。

组队协作 · AGENT TEAMS

一句指令，多位 Hero 并行作战

复杂任务不再单打独斗——孔明出设计、文远写代码、希仁补测试，三位 Hero 同时在各自 pane 里推进，互相通信，合力交付。install.sh 会自动安装 tmux；按提示合并 settings.json 即可启用分屏模式。

你说 "组队完成登录模块"
孔 孔明 设计 + 拆任务 opus
文 文远 写代码 sonnet
希 希仁 写测试 haiku
$ tmux new -s work $ claude 进入 tmux 会话后告诉 Claude: "组队 3 位 Agent"

自动分屏

每位 Hero 独占一个 tmux pane，实时查看各自进度。install.sh 自动安装 tmux；按提示合并 settings.json 即可启用。

智能分配模型

复杂决策用 opus，写代码用 sonnet，轻量任务用 haiku——按任务难度分配模型，兼顾质量与成本。

互相通信

Hero 之间可以发消息、共享进展、协调冲突。孔明出方案后通知文远实现，文远写完通知希仁补测试。

安装 · GET STARTED

一条命令，加入队伍

克隆后跑一次 install.sh，把共享 skills / agents / hooks 软链进你的 ~/.claude——逐项软链、已有文件自动备份，绝不污染你原有的配置。之后 git pull 即全员生效，无需重装。

$ git clone git@gitlab.corp.yaduo.com:full-stack-ai/claude-hero.git && cd claude-hero && bash install.sh 复制这一行 · 十分钟接入

这条命令做了什么

  1. 1

    逐项软链

    把 skills / agents / hooks 子项逐个软链进 ~/.claude，不整目录覆盖。

  2. 2

    自动备份

    目标已存在且非本仓库软链时，先备份 *.bak.<时间戳> 再建链。

  3. 3

    模板手动合并

    CLAUDE.md / settings.json / .mcp.json 含密钥，不自动写入，仅提示按需合并。

  4. 4

    幂等可重跑

    已是正确软链则跳过；git pull 后全员生效，改任意 SKILL.md 即时见效。

卸载 · UNINSTALL

一条命令，安全退出

跑一次 uninstall.sh，安全移除 本仓库 的软链——只删除指向本仓库的链接，绝不误删你的个人配置与备份。

$ cd claude-hero && bash uninstall.sh 复制这一行 · 一键卸载

这条命令做了什么

  1. 1

    扫描软链

    读取 manifest.yaml，遍历 ~/.claude 下所有 link 模式条目。

  2. 2

    只删本仓库

    逐条检查 symlink 指向——仅删除指向本仓库内部的，其余一律保留。

  3. 3

    保留个人配置

    CLAUDE.md / settings.json / .mcp.json 是 template 模式，不会被卸载；*.bak.* 备份文件同样安全。

  4. 4

    可逆可重连

    仓库代码原封不动，随时 bash install.sh 即可恢复全部 Hero 能力。

进阶 · BUILD YOUR PILOT

一条命令，为项目造一位领航员

领航员是某个服务的「只读知识层」——懂业务定位、技术栈、代码地图与对外契约。开荒全自动：给一个项目路径，花名可选（留空自动分配），hero-init 跑完六阶段，直接产出 hero-<lang>-<project> 并提交 Git 分支。

$ bash scripts/hero-init.sh <项目路径> [花名] <项目路径> [花名] · 花名可选（留空自动分配），取自历史人物字号，不与现有 Hero 冲突

这条命令背后的六个阶段

  1. 1

    检测项目布局

    识别构建工具与模块结构——单模块与多模块差别很大，先探出真实包根。

  2. 2

    检测技术栈

    读 pom.xml / build.gradle 认框架与中间件，决定模板——不默认 Spring。

  3. 3

    收集代码证据

    抓入口点、配置文件、对外契约与语义种子，作为生成素材。

  4. 4

    填充模板

    套四段式 description（定位 / 触发词 / 路由 / 边界）写出 agents/{name}.md。

  5. 5

    反伪造验证

    校验路径 / 技术栈 / 关键词，正文引用的每个类都要真实命中，零编造。

  6. 6

    Git 分支 + MR 指引

    自动建 feat/init-* 分支并提交，输出 MR 指引——不会自动 push。

开荒完成后注册进 .refresh-state.json，即纳入 hero 刷新 保鲜；完整手册见 docs/navigator-lifecycle-handbook.md。
