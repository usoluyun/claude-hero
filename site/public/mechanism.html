Skill Dispatch · Skill 调度

四大核心 Skill，覆盖全生命周期

每个 Skill 都是一种标准化的工作流，
通过配置文件定义触发条件、执行步骤和输出格式。 

┌─────────────────────────────────────────────────────────────┐
│  hero-dispatch: 意图路由决策树                                │
└─────────────────────────────────────────────────────────────┘

输入参数
  - user_input: 自由文本（如 "开发用户认证模块"）

处理流程
  1. 意图识别
     - 调用 LLM 对用户输入进行语义分析
     - 提取关键实体：项目名、功能名、优先级、目标分支

  2. Lane 匹配（8 条预定义车道）
     - prd: PRD 驱动开发
     - task: 普通任务执行
     - bugfix: 问题修复
     - refactor: 重构优化
     - security: 安全审计
     - perf: 性能优化
     - research: 技术调研
     - question: 咨询问答

  3. 参数完整性检查
     - 必填字段验证（项目 ID、功能名）
     - 缺失字段自动回退询问用户

  4. 确认门控（Confirmation Gate）
     - 弹出确认面板，显示解析结果
     - 用户确认或修改后，提交到下一步

输出结果
  - 确认后的 Lane 配置对象
  - 完整的任务上下文（含 Git 分支信息）

代码示例
  # skills/hero-dispatch/SKILL.md
  on_trigger:
    - pattern: "hero"
    - match: free_form_intent

  routing:
    step_1: semantic_analysis(user_input)
    step_2: match_lane(keywords, entities)
    step_3: validate_params(lane_schema)
    step_4: confirm_gate(user_review) → next_skill
              
┌─────────────────────────────────────────────────────────────┐
│  hero-prd-to-java: PRD 驱动开发流水线                        │
└─────────────────────────────────────────────────────────────┘

输入参数
  - prd_url: 飞书文档链接
  - project_id: GitLab 项目标识
  - feature_name: 功能名称（可选）
  - target_branch: 目标分支（默认 main）

处理流程
  Wave 1: 分析与设计（孔明）
    1.1 拉取 PRD 文档（via lark-cli）
    1.2 解析功能需求、非功能需求、优先级
    1.3 设计架构方案、数据模型、API 接口
    1.4 制定 Sprint 计划（含人力评估）
    1.5 输出设计文档（Markdown）

  Wave 2: 并行实现（文远 + 子长 + 玄成）
    2.1 创建功能分支（via glab branch）
    2.2 创建空工程骨架（via hero-init）
    2.3 并行开发：
        - 文远：业务逻辑实现
        - 子长：数据库 SQL
        - 玄成：代码审查（实时）
    2.4 提交代码到功能分支

  Wave 3: 验证与合并（希仁 + 鹏举）
    3.1 运行自动化测试（via playwright）
    3.2 安全扫描与审计（via mcp-gitlab）
    3.3 更新设计文档（含变更记录）
    3.4 推送合并请求（via glab mr）

输出结果
  - 完整功能分支（含代码 + 测试 + 文档）
  - GitLab 合并请求（MR）
  - 安全审计报告 + 测试覆盖率报告
              
┌─────────────────────────────────────────────────────────────┐
│  hero-init: 项目初始化流程                                   │
└─────────────────────────────────────────────────────────────┘

输入参数
  - project_id: GitLab 项目 ID
  - project_name: 项目名称
  - framework: 技术栈（如 Spring Boot, Flask）
  - package: 包名（如 com.atour.ecrm）

处理流程
  1. 项目探测
     - 检查目标目录是否已存在
     - 分析项目结构（Maven / Gradle / npm）

  2. 技术栈确认
     - 识别当前使用的框架版本
     - 检测依赖管理工具（Maven / Gradle / npm）

  3. 目录结构规划
     - 按框架最佳实践生成目录树
     - 规划配置文件布局

  4. 骨架生成
     - 创建 pom.xml / build.gradle / package.json
     - 生成基础代码文件（Controller, Service, etc.）
     - 配置开发环境（.env, IDE settings）

  5. 依赖注入
     - 根据技术栈安装必要依赖
     - 配置常用工具（Lombok, Swagger, etc.）

  6. 初始化 Git
     - 创建 .gitignore
     - 初始化提交（initial commit）

输出结果
  - 完整的项目骨架
  - 基础开发环境配置
  - Git 初始提交
              
┌─────────────────────────────────────────────────────────────┐
│  hero-refresh: 知识与技能保鲜机制                             │
└─────────────────────────────────────────────────────────────┘

输入参数
  - skill_name: 要刷新的 Skill 名称（可选）
  - force: 强制刷新（跳过缓存检查）
  - dry_run: 干跑模式（仅预览，不执行）

处理流程
  Step 1: 状态检查
    - 扫描本地 ~/.claude/skills 目录
    - 检查每个 Skill 的版本信息
    - 对比远程仓库最新版本

  Step 2: 差异分析
    - 识别已安装的 Skill
    - 计算本地与远程的版本差异
    - 分析变更内容（changelog）

  Step 3: 刷新策略决策
    - 增量安装：仅安装新增 Skill
    - 版本更新：更新到最新版本
    - 冲突检测：检查本地修改是否冲突

  Step 4: 执行刷新
    - 下载并安装 Skill 文件
    - 备份本地修改（.bak 文件）
    - 验证安装完整性

  Step 5: 环境同步
    - 更新 ~/.claude/CLAUDE.md（如有新增 Skill）
    - 刷新 CLI 工具符号链接
    - 验证工具链可用性

输出结果
  - 刷新报告（成功 / 失败 / 跳过的 Skill）
  - 备份文件（含冲突的本地修改）
  - 环境健康状态报告
